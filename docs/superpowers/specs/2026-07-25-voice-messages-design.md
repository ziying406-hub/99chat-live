# 语音消息与自动播放设计

## 目标

将现有的语音占位消息替换为可录制、上传、播放和按设置自动播放的真实语音消息。

## 范围

- 在聊天输入区切换到语音模式。
- 按住录音，松开后发送；录音少于一秒时取消。
- 通过浏览器 `MediaRecorder` 生成音频文件并使用现有文件上传流程保存。
- 语音消息气泡显示时长，并支持播放、暂停和播放进度。
- 打开“自动播放语音”时，仅自动播放当前可见聊天窗口中新收到的语音一次。

## 交互

1. 点击麦克风按钮进入语音模式。
2. 按住“按住录音”开始录制，界面显示录制时长和取消提示。
3. 松开按钮后：
   - 小于一秒：取消，不发送消息。
   - 一秒或以上：上传音频并创建 `voice` 消息。
4. 收到语音消息时，点击播放按钮可以开始或暂停播放。
5. 自动播放关闭时，任何收到的语音均不自动播放。
6. 自动播放开启时，只有会话已打开且页面可见的新增语音才自动播放，历史消息不会自动播放。

## 数据与兼容

- `voice` 消息继续使用现有消息类型。
- 音频文件写入现有上传存储，并放入消息 `attachment` 中，包含 URL、MIME 类型、文件名和大小。
- `body` 保存四舍五入后的秒数，供消息列表、搜索和无音频回退显示。
- 旧的无附件语音消息仍显示为时长文本，不尝试播放。

## 错误处理

- 浏览器不支持录音或用户拒绝麦克风权限：显示明确提示，不生成伪造语音消息。
- 上传失败：发送失败状态可重试，且不会丢失本次录音的数据。
- 页面离开、切换会话或取消录音：停止录音流并清理临时资源。

## 验证标准

- 可在桌面和手机浏览器录制一段至少一秒的语音并成功发送。
- 收件方刷新页面后仍可播放该语音。
- 点击播放和暂停符合状态，时长与进度正常更新。
- 自动播放关闭时不播放，开启时仅播放当前打开会话中新到的语音一次。
- 拒绝麦克风权限和短录音不会产生语音消息。
